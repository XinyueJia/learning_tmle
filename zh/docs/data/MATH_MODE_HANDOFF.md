# 对象图数学阅读模式交接

`zh/src/object-grammar.js` 现在区分数学解释与Julia实现。数学模式不生成 `.ov-code`、可运行Julia片段或 `data-julia-name` 属性；Julia模式继续显示原有精确语句。两种模式从同一数据对象取值，不改变拟合、患者行序、系数排列、概率或全队列汇总。

当前 `OBJECT_STAGES` 实际共有18个阶段：第0章5个，第1章13个。测试遍历全部阶段，并额外覆盖预测输入的全1、全0和实际A三种场景，没有按请求中的阶段数虚构新图。

## 数学模式保留的教学内容

- 拟合Q使用17列设计矩阵Z加实际A，以实际Y为结果；拟合g的折叠区域独立说明以A为结果、只用Z，并画出逐人处理概率。数学模式里不再藏着固定的Julia函数调用。
- 同一设计矩阵与两种预测输入A仍给出两列Q预测；实际A的选择通过逐行保留一项、另一项乘0来解释。
- 固定参考均值卡只写数学对象μ及其作用。样本风险与参考均值的数值关系在文字中解释，不再把程序变量赋值当作数学标签。
- 整列求和用Σ、Σᵢ或中文“求和”；逐元素乘法用⊙；向量收缩到标量时明确说明对全部n人平均。组概率已经含人数权重，不再除以2。
- 概率替换使用指示向量1{y=z}说明新增质量的位置；逐人IF使用每个Yᵢ减同一个μ说明操作。不会在数学说明中引入语言特有点运算符或数值类型。
- 矩阵、向量和标量维度、患者i与结局y及特征系数三种排列方式保持可见。原始CSV字段名属于数据来源信息，仍保留。

工具条保留“Julia运算”选项，但静态形状说明使用数学表达；Julia中 `Vector` 的实际 `size` 与图上n×1形状的区别，仅在Julia模式每章首幅对象图显示。无需在运行时切换图例或工具条段落。

Julia模式的代码行没有改写；现有测试继续逐字核对 `object_ch00.jl`、`object_ch01.jl`。Python或R的未来入口可以另加，不需要先从数学图里删除Julia实现文字。

## 表达式容器接口

私有 `expr(label, content)` 现在返回：

```html
<div class="ov-expression-scroll" tabindex="0" role="region" aria-label="…，可横向滚动">
  <div class="ov-expression" role="group" aria-label="…">…</div>
</div>
```

外层是可用键盘聚焦的滚动区域；内层保留原有对象组及其语义标签。渲染器不设置高度，CSS和实际滚动交互由主代理负责。

`syntax` 仍生成 `ov-syntax`。非空token去除首尾空白后，如果只含运算或分组符号（例如+、−、×、÷、⊙、/、括号），额外加 `ov-operator`。长操作词与函数名保留普通 `ov-syntax`，方便CSS分别设置字号；箭头保留已有 `ov-arrow`。

```sh
node --test tests/zh/object-grammar.test.js tests/zh/math-reading-mode.test.js
```

实际执行Julia工作簿时，指定现有安装的直接可执行文件为 `JULIA_BIN`，并将 `JULIA_DEPOT_PATH` 指向临时目录，避免juliaup配置锁与用户缓存写入限制。本次补跑包含两个工作簿，不把默认启动器失败造成的跳过记作通过。
